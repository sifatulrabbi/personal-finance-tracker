# Keep queryable current state beside the revision evidence

This extends ADR 0002. A transaction's date, kind, wallets, category, and BDT value lived only in its revision payload, so lists and monthly totals parsed JSON for every record and could not use an index, and every write summed the wallet's whole history to check its balance limit. At 30,000 records the first list page took about 116 ms and a monthly total about 68 ms, growing with history.

Revision payloads stay unchanged, as the evidence of what each version said and who wrote it. Each `transactions` row now also carries its current revision's facts as typed columns (`kind`, `date`, `wallet_id`, `to_wallet_id`, `category_id`, `bdt_minor`, `created_at`, and a unique write position `seq`), and each wallet caches `balance_minor`. These are derived values, never a second source: the columns are computed from the payload by the same Go reading every other read uses (legacy categories resolve to Others, a debit card's records keep the card as `wallet_id`), and they are written in the same transaction as the revision. Wallet entries remain the balance source of truth; the cache changes only through an insert trigger on `wallet_entries`, inside the transaction that posts the entry, and entries are append-only. `VerifyDerivedState` compares every column with its payload and every cached balance with the sum of its entries; tests run it after mixed writes, corrections, voids, and upgrades, and `migrate` runs it before committing any migration, so a backfill that disagrees with the application leaves the database unchanged. We chose stored columns over expression indexes on JSON because the Others fallback and the decimal-to-minor-unit conversion are application rules, and over dropping the payload because the payload is the audit evidence.

The store opens two pools on the SQLite file: one writer connection whose transactions begin with `BEGIN IMMEDIATE`, and a few read-only connections with deferred transactions. In WAL mode a read sees one committed snapshot and never waits for a writer, so a slow write no longer delays `/healthz` or page loads. `synchronous` stays `FULL`. Code reaches the pools only through `Read`, `Change`, and `Write` of `sqlite.Store` (ADR 0013), whose closures receive a transaction bound to the request context; a test rejects any transaction code that touches a pool, calls a public store method, or uses an outer context, since with one writer connection that would deadlock.

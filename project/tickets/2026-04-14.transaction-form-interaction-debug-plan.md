# Transaction Form Interaction Debug Plan

Date: 2026-04-14

## Problem Summary

The transaction creation drawers on `/transactions` are not usable:

- Desktop dropdown triggers do not respond reliably.
- Mobile dropdowns can open, but choosing an item does not register.
- The category/origin combobox inputs and native date inputs are also affected.

This failure pattern points to interaction handling in the drawer layer rather than isolated React state bugs in each field.

## Root-Cause Hypothesis

The transaction forms live inside Vaul drawers. Vaul captures pointer gestures on drawer content so the sheet can be dragged, and its implementation only skips that behavior for targets inside a `data-vaul-no-drag` subtree or when the drawer is configured to drag from the handle only.

The transaction drawers contain several controls that depend on uninterrupted pointer sequences and external popups:

- Base UI `Select`
- Base UI `Combobox`
- native `input[type="date"]`

If drawer dragging captures those interactions first, the UI can appear open while item selection, focus, or native picker interaction never completes.

## Work Plan

1. Mark the transaction form interaction region as non-draggable so Vaul does not steal pointer events from inputs, selects, and comboboxes.
2. If popup interactions still escape the drawer stacking context, route select/combobox portals into the drawer content instead of the document body.
3. Add regression coverage for the transaction form helpers or component behavior so we keep this interaction bug from returning silently.
4. Validate the touched code with focused Bun checks and run `bun run format` as the final cleanup step.

## Explicit Non-Goals

- Reworking unrelated account/settings drawers unless the shared fix clearly improves them without changing behavior.
- Refactoring the transaction stores or API contracts unless the investigation finds an actual state bug beyond the drawer interaction issue.

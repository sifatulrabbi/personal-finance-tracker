# Central Server Config Provider Implementation Plan

## Summary

Introduce a central server-only config provider for active application configuration, starting with the existing database connection env vars. The provider will use Zod for deterministic runtime validation, expose DI-friendly factory functions for tests, and keep lazy cached runtime access for the application path.

## Decisions

- Add `zod` as a runtime dependency because config parsing happens at runtime.
- Keep this first slice server-only under `src/libs/server/config.ts`.
- Validate runtime app config and test-only config through separate factory functions so production does not require `TEST_DATABASE_URL`.
- Keep `src/libs/server/db/config.ts` as an import-compatible shim backed by the central provider.
- Do not add public/client config, auth placeholders, feature flags, secrets management, or a React provider in this slice.

## Implementation Steps

1. Add Zod with Bun.
2. Add `src/libs/server/config.ts` with typed `createAppConfig`, `getAppConfig`, `createTestAppConfig`, and `resetAppConfigForTests` exports.
3. Add unit tests for runtime config parsing, test config parsing, validation failures, lazy caching, and cache reset behavior.
4. Refactor `src/libs/server/db/config.ts` into a compatibility shim.
5. Update `src/libs/server/db/client.ts` to read from the central provider while preserving DI-friendly env injection.
6. Update existing DB config tests for the new deterministic validation messages where needed.
7. Run Bun unit tests, integration tests if Postgres is available, lint, typecheck, and formatting.

## Public/Internal Interfaces

- `EnvironmentMap`

- `AppConfigDependencies`
- `createAppConfig(dependencies?)`
- `getAppConfig()`
- `createTestAppConfig(dependencies?)`
- `resetAppConfigForTests()`

## Test Plan

- `createAppConfig()` reads `DATABASE_URL`.
- `createAppConfig()` does not require `TEST_DATABASE_URL`.
- `createAppConfig()` rejects missing, empty, and non-Postgres `DATABASE_URL` values.
- `createTestAppConfig()` reads `TEST_DATABASE_URL`.
- `createTestAppConfig()` does not require `DATABASE_URL`.
- `createTestAppConfig()` rejects missing `TEST_DATABASE_URL`.
- `getAppConfig()` caches the parsed runtime config.
- `resetAppConfigForTests()` clears the cached runtime config.
- Existing DB config and client tests continue to pass.

# Transaction Sheet — Frontend Rewrite

**Date:** 2026-04-18
**Status:** Planning → In Progress
**Branch:** `rework`
**Supersedes:** `tickets/2026-04-14.transaction-form-interaction-debug-plan.md`,
`tickets/2026-04-14.transaction-form-rewrite-plan.md`

## Problem

The current "add transaction" UX on `/transactions` (and the separate
`TransferDrawer` on `/accounts`) is structurally broken — not just in surface
behaviour but in how the pieces are modelled.

1. **Duplicated components.** `ExpenseDrawer` and `IncomeDrawer` are ~95 %
   identical code. `TransferDrawer` lives under `/accounts`, bypasses
   `transaction-store`, and calls `fetch` directly — so creating a transfer
   does not refresh the transactions list.
2. **State sprawl.** Each drawer uses 8–10 `useState` hooks, a hand-rolled
   `resetForm`, and a `resetKey` remount hack to work around internal combobox
   state drift. Validity is an ad-hoc truthiness chain. No validation library,
   no surfaced field errors.
3. **Combobox value drift.** `CreatableCombobox` keeps its own `inputText`
   state that decouples from the parent `value` prop. The category/origin
   fields are represented as two correlated values (`id`+`isNew`) that can
   desync.
4. **Vaul portal conflicts.** The Vaul bottom drawer captures pointer gestures
   and fights base-ui Select/Combobox portals. `DrawerInteractionBoundary`
   patches it by disabling drag and routing portals into the drawer subtree —
   we are fighting the primitive.
5. **Store inconsistency.** The store exposes `createExpense` and
   `createIncome` but no `createTransfer`; transfers are wired through raw
   `fetch` inside `transfer-drawer.tsx`.

## Conceptual Reframe

A transaction is a single concept with a discriminated variant:
`expense | income | transfer`. The variant determines which fields are
required. Modelling it that way collapses three drawers into one form and
mirrors how the backend already accepts these inputs.

| Field                              | expense | income | transfer   |
| ---------------------------------- | ------- | ------ | ---------- |
| person                             | ✓       | ✓      | ✓          |
| account                            | ✓       | ✓      | —          |
| sourceAccount / destinationAccount | —       | —      | ✓          |
| category                           | ✓       | ✓      | —          |
| origin                             | —       | ✓      | —          |
| amount + currency                  | ✓       | ✓      | ✓ BDT only |
| transactionDate                    | ✓       | ✓      | ✓          |
| description                        | opt     | opt    | opt        |

## Decisions (confirmed)

1. **Container.** Replace the Vaul `Drawer` with the existing `Sheet`
   component (base-ui `Dialog`, side = right). Same portal model as base-ui
   Select/Combobox — the interaction bug class disappears. `DrawerInteraction­Boundary`
   becomes unnecessary and is deleted.
2. **Form state.** Adopt `react-hook-form` + `@hookform/resolvers` with a Zod
   discriminated-union schema. Two new runtime deps, pays back multiple
   hundred lines of imperative state code.
3. **Unified sheet.** One `TransactionSheet` component handles
   create-expense / create-income / create-transfer / edit-expense /
   edit-income. Both `/transactions` and `/accounts` mount it, the latter
   with `defaultType="transfer"`.
4. **Optimistic list updates are out of scope.** The store keeps its current
   "refetch on success" model. A follow-up can add optimistic updates.

## Architecture

```
TransactionSheet (client)
├── <Sheet> (base-ui Dialog, side=right)
│   └── <SheetContent>
│       ├── SheetHeader (title switches on mode/type)
│       ├── TypeTabs (hidden in edit mode)
│       │   – expense / income / transfer
│       ├── <form> (react-hook-form)
│       │   ├── PersonField (Select, always)
│       │   ├── AccountField (Select, expense+income only)
│       │   ├── SourceAccountField (Select, transfer only)
│       │   ├── DestinationAccountField (Select, transfer only)
│       │   ├── CategoryField (CreatableCombobox, expense+income)
│       │   ├── OriginField (CreatableCombobox, income only)
│       │   ├── AmountCurrencyField (transfer → BDT only)
│       │   ├── DateField
│       │   └── DescriptionField
│       └── SheetFooter (Cancel, Submit)
```

### Data flow

```
form values ─► toTransactionInput(values)
             └► store action (createExpense | createIncome |
                 createTransfer | updateTransaction)
             └► POST/PATCH
             └► store.fetchTransactions (or accountStore.fetchAccounts
                  for balance refresh after transfer)
```

### Key module boundaries

- `src/libs/client/transaction-schemas.ts` — Zod discriminated-union schema
  - `toCreateExpenseInput / toCreateIncomeInput / toCreateTransferInput /
toUpdateTransactionInput` mappers (pure, unit-testable).
- `src/libs/client/transaction-form.ts` — pure helpers:
  `defaultValuesFor(type)`, `defaultValuesFromTransaction(t)`,
  `getTodayString()`.
- `src/stores/transaction-store.ts` — add `createTransfer`. Ensure it also
  triggers `accountStore.fetchAccounts` via the caller (balances shift).
- `src/app/(authenticated)/transactions/transaction-sheet.tsx` — the one
  component.
- `src/app/(authenticated)/transactions/creatable-combobox.tsx` —
  refactor to controlled-only (single `value` of shape
  `{ kind: 'existing', id } | { kind: 'new', name } | null`) and accept
  an `error` prop. Compatible with RHF `Controller`.

## Step-by-step implementation

1. **Deps.** `bun add react-hook-form @hookform/resolvers`.
2. **Client schemas + mappers** — write `transaction-schemas.ts` and
   `transaction-form.ts` with unit tests. Start here so the rest compiles
   against typed inputs.
3. **Store: `createTransfer`.** Add action + input type to
   `transaction-store.ts`; caller also refreshes accounts.
4. **CreatableCombobox refactor.** Controlled `value` of shape
   `{ kind: 'existing', id } | { kind: 'new', name } | null`, plus `error`
   prop. Keep existing static-markup tests passing or update them.
5. **`CurrencyAmountField`.** Pure presentational field wired via RHF
   `Controller`. Renders amount input, currency select, BDT preview.
6. **`TransactionSheet`.** Build the component: Sheet container,
   type tabs, RHF form, conditional field rendering, submit dispatcher.
7. **Page wiring.**
   - `transactions-page-client.tsx`: mount `TransactionSheet`, remove the
     two old drawer imports.
   - `accounts-page-client.tsx`: mount `TransactionSheet` with
     `defaultType="transfer"`, remove `TransferDrawer` import.
8. **Delete legacy files** listed under "Deleted".
9. **Verify.** `bun run typecheck`, `bun test src/libs`, format pass.
10. **Chore.** `bun run format`.

## Testing

- **Schema unit tests** — valid/invalid for each variant; rejects
  both-and-neither cases (category id + name; origin id + name); rejects
  self-transfer.
- **Mapper unit tests** — form values → API input shape for every variant
  and for update-mode partial payload.
- **`transaction-form.ts` helpers** — default values for create,
  default values from an existing transaction (expense, income).
- **Static render smoke** for `TransactionSheet` — renders without crashing
  for each variant in create mode (covers conditional-field visibility).
- Existing API route tests are untouched.

Interaction testing (click tabs, fill fields, submit) is **not** included in
this plan because the repo currently has no jsdom/happy-dom setup. A
follow-up plan can introduce `@testing-library/react` + `happy-dom` for
browser-level tests.

## Non-goals

- Backend changes. Schemas, routes, logging are untouched.
- Optimistic list updates / list-state insertion on success.
- Editing transfers (backend blocks it; UI will hide the Edit button for
  transfer rows — a tiny list-side tweak, tracked inline).
- Reworking `account-form-drawer.tsx` (still uses Vaul; out of scope).

## Risks & mitigations

- **RHF + base-ui Select integration.** Select is uncontrolled-friendly;
  wire via `<Controller>` with `field.value` / `field.onChange`. Mirror for
  Combobox.
- **Zod v4 discriminated union ergonomics.** Base object per variant +
  `.extend({ type: z.literal(...) })` + `z.discriminatedUnion("type", [...])`.
- **Combobox refactor may affect future callers.** Currently only used in
  the two drawers (being deleted). Safe to refactor.
- **Currency rate snapshot.** Client does not snapshot — backend does at
  create time. We send only `{ amount, currency }`. No change needed.

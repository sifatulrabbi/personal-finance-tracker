**Date**: 2026-04-10
**Status**: Draft for review

---

## Overview

The app has 4 authenticated pages (Dashboard, Accounts, Transactions, Settings) plus a Sign-in page. All pages are mobile-first with a bottom tab navigation bar. Desktop gets the same layout scaled up — no separate sidebar navigation.

All data interactions (create, edit, delete) happen via **sheets** (bottom drawers on mobile, side sheets on desktop) or **dialogs** — never separate pages. This keeps navigation shallow and mobile-friendly.

## Page 2: Dashboard (`/dashboard`)

The landing page after login. Provides a quick financial snapshot and fast entry points.

### Sections

1. **Balance summary cards** (horizontal scroll on mobile)
   - Total balance across all accounts (sum of `currentBalance`)
   - Current month income total
   - Current month expense total

2. **Quick actions** (row of buttons)
   - "+ Expense" → opens expense sheet
   - "+ Income" → opens income sheet
   - "Transfer" → opens transfer sheet

3. **Recent transactions** (last 5)
   - Compact cards showing: date, description/category, amount, type color indicator
   - "View all" link → navigates to `/transactions`

### Data requirements

- `GET /api/households/[id]/accounts` (for balance totals)
- `GET /api/households/[id]/transactions?pageSize=5` (for recent list)

## Page 3: Accounts (`/accounts`)

Manage money-holding accounts and initiate transfers.

### Sections

1. **Household total** (sticky header area)
   - Sum of all account balances, formatted as currency

2. **Account cards** (vertical list)
   - Each card shows: name, description, current balance
   - Tap card → expand inline to reveal **Edit** and **Delete** actions
   - Delete shows confirmation dialog; blocked with message if account has transactions (409)

3. **Floating action button** (bottom-right, above tab bar)
   - "+ Add Account" → opens create account sheet

### Sheets

**Create Account Sheet**

- Fields: Name (required), Description (optional), Initial Balance (required, currency input)
- Submit → `POST /api/households/[id]/accounts`

**Edit Account Sheet**

- Fields: Name, Description (balance not editable directly)
- Submit → `PATCH /api/households/[id]/accounts/[accountId]`

**Transfer Sheet** (accessible from quick actions on dashboard or an action on this page)

- Fields: From Account (select), To Account (select), Person (select), Amount, Date, Description (optional)
- Validation: from !== to
- Submit → `POST /api/households/[id]/transfers`

### Data requirements

- `GET /api/households/[id]/accounts`
- `GET /api/households/[id]/people` (for transfer person picker)

## Page 4: Transactions (`/transactions`)

Browse, filter, and create transactions.

### Sections

1. **Type filter tabs** (horizontal, sticky below header)
   - All | Expenses | Income | Transfers
   - Maps to `?type=expense`, `?type=income`, `?type=transfer` query param

2. **Filter bar** (collapsible, below tabs)
   - Person picker (dropdown/select)
   - Category picker (dropdown/select)
   - Account picker (dropdown/select)
   - Each filter maps to query params on the transactions API

3. **Transaction list** (vertical, cards not table rows)
   - Each card shows:
     - Date (left-aligned)
     - Category name + person name
     - Account name
     - Amount with color: red for expense, green for income, blue for transfer
     - Description (if present, truncated)
     - Transfer indicator badge if part of a transfer pair
   - Sorted reverse-chronological (API default)

4. **Pagination** (bottom of list)
   - "Load more" button or page number controls
   - Uses `page` + `pageSize` query params

5. **Floating action button** (bottom-right, above tab bar)
   - Tap → shows choice: "Expense" or "Income"
   - Selecting one opens the corresponding sheet

### Sheets

**Expense Sheet**

- Fields:
  - Person (select, required)
  - Account (select, required)
  - Category (combobox: pick existing or type new name to auto-create, required)
  - Amount (currency input, required)
  - Date (date picker, defaults to today, required)
  - Description (text, optional)
- Submit → `POST /api/households/[id]/transactions/expenses`

**Income Sheet**

- Fields:
  - Person (select, required)
  - Account (select, required)
  - Category (combobox: pick existing or type new, required)
  - Origin (combobox: pick existing or type new, required)
  - Amount (currency input, required)
  - Date (date picker, defaults to today, required)
  - Description (text, optional)
- Submit → `POST /api/households/[id]/transactions/income`

### Data requirements

- `GET /api/households/[id]/transactions?type=...&personId=...&categoryId=...&accountId=...&page=...&pageSize=...`
- `GET /api/households/[id]/people` (filter + form picker)
- `GET /api/households/[id]/categories` (filter + form combobox)
- `GET /api/households/[id]/accounts` (filter + form picker)
- `GET /api/households/[id]/origins` (income form combobox)

## Page 5: Settings (`/settings`)

Manage household configuration: people, app members, categories, and origins.

### Layout

Vertical sections with headers, each independently scrollable. On mobile this is a single scrolling page with clear section dividers. No tabs — all sections are visible on one scroll to keep things simple and discoverable.

### Section A: People

Household members used for tagging transactions (distinct from app users).

- List of people cards: name, "(Default)" badge for the Household person
- Each non-default person has a **Delete** button (with confirmation dialog)
- Default person ("Household") cannot be deleted — delete button hidden or disabled
- **"+ Add Person"** button at top of section → inline form or sheet
  - Field: Name (required)
  - Submit → `POST /api/households/[id]/people`

### Section B: App Members

Users who can sign in to the app.

- List of member cards: name, email, status badge ("Active" / "Invited")
- **"+ Invite"** button → inline form or sheet
  - Field: Email (required, validated)
  - Submit → `POST /api/households/[id]/users`
- No delete action for members (not in requirements)

### Section C: Categories

Tags for transactions.

- List of category cards: name, description
- Each category has a **Delete** button
  - Blocked with message if category is used by transactions (409)
- **"+ Add Category"** button → inline form or sheet
  - Fields: Name (required), Description (optional)
  - Submit → `POST /api/households/[id]/categories`

### Section D: Origins

Income sources (clients, companies).

- List of origin cards: name, description
- Each origin has a **Delete** button
  - Blocked with message if origin is used by transactions (409)
- **"+ Add Origin"** button → inline form or sheet
  - Fields: Name (required), Description (optional)
  - Submit → `POST /api/households/[id]/origins`

### Data requirements

- `GET /api/households/[id]/people`
- `GET /api/households/[id]/users`
- `GET /api/households/[id]/categories`
- `GET /api/households/[id]/origins`

## Shared Components Needed

These are the reusable components beyond what shadcn/ui provides out of the box:

| Component         | Purpose                                                                              |
| ----------------- | ------------------------------------------------------------------------------------ |
| `BottomNav`       | Fixed bottom tab bar for mobile navigation                                           |
| `PageHeader`      | Consistent page title + optional action button                                       |
| `CurrencyDisplay` | Formats minor-unit integers to display currency (e.g. 150000 → "$1,500.00")          |
| `CurrencyInput`   | Input that accepts decimal amounts, converts to minor units on submit                |
| `ComboboxField`   | Searchable dropdown with free-text "create new" option (for category/origin pickers) |
| `EntityCard`      | Reusable card for list items with name, subtitle, and trailing action                |
| `EmptyState`      | Placeholder shown when a list has no items yet                                       |
| `TypeBadge`       | Colored badge for transaction type (expense/income/transfer)                         |
| `ConfirmDialog`   | Reusable confirmation dialog for destructive actions                                 |
| `FormSheet`       | Bottom sheet wrapper for create/edit forms                                           |

### shadcn/ui components to install

- `sheet` (bottom drawer / side panel)
- `dialog` (confirmation modals)
- `select` (dropdowns for person/account pickers)
- `command` (combobox base for category/origin pickers)
- `popover` (combobox container)
- `input`, `textarea`, `label` (form fields)
- `badge` (status indicators)
- `card` (list items, summary cards)
- `tabs` (transaction type filter)
- `separator` (section dividers in settings)
- `skeleton` (loading states)
- `toast` / `sonner` (success/error feedback)

## Client-Side Data Strategy

All pages fetch data from the mock API routes (already built). Strategy:

1. **Server components** for initial page load — fetch data server-side where possible
2. **Client components** for interactive parts — forms, filters, sheets
3. **SWR or simple `fetch` + `useState`** for client-side data fetching and cache invalidation after mutations
4. **No global state library** — household ID comes from the session, data is fetched per-page
5. After a mutation (create/delete/update), refetch the relevant list to reflect changes

# Plan: Transactions Page

## Context

The transactions page is the core feature of the finance tracker — the place where users record expenses and income, and browse their transaction history. The app already has working API routes (GET transactions with filters/pagination, POST expense/income/transfer), existing Zustand stores for accounts/people/categories/origins/currencies, and a well-established page pattern from the accounts page. What's missing is the transaction store and all frontend components.

---

## Key Design Decisions

1. **New Transaction Store** — Zustand store following the exact same factory+provider pattern as `account-store.ts`. Manages transactions, pagination meta, and filter state.

2. **Filter-driven fetching** — The store holds filter state (`type`, `personId`, `categoryId`, `accountId`). The orchestrator component watches filters via `useEffect` and refetches when they change. This keeps the store as single source of truth.

3. **Transfer tab is client-side** — The API only supports `type=income|expense`. For "Transfers" tab, fetch all transactions and client-side filter by `transferGroupId !== null`.

4. **Creatable Combobox** — A reusable component wrapping the base-ui Combobox for category/origin pickers. Shows existing items plus a "Create: [typed text]" option when no exact match exists. Used in both expense and income drawers.

5. **FAB for Expense, Header button for Income** — Mirrors the accounts page pattern (FAB for primary action, header action for secondary). Expense is the most common action.

6. **Date-grouped list** — Transactions grouped by `transactionDate`, displayed as "Today", "Yesterday", or formatted date. Grouping is a pure function since data arrives pre-sorted.

## Step 1: Transaction Store

**New file:** `src/stores/transaction-store.ts`

Types:

```
Transaction — mirrors MockTransaction shape (with currency fields)
TransactionFilters — { type: "all"|"expense"|"income"|"transfer", personId, categoryId, accountId }
TransactionMeta — { total, page, pageSize }
CreateExpenseInput — { accountId, personId, categoryId?, categoryName?, amount, currency?, description?, transactionDate }
CreateIncomeInput — extends CreateExpenseInput + { originId?, originName? }
```

State: `transactions[]`, `meta`, `filters`, `loading`, `loadingMore`, `error`

Actions:

- `fetchTransactions(householdId)` — builds URL query from `filters`, fetches page 1, replaces `transactions` and `meta`
- `loadMore(householdId)` — fetches `meta.page + 1`, appends to `transactions`, updates `meta`
- `setFilters(partial)` — merges into filters (does NOT auto-refetch; the component's useEffect handles that)
- `createExpense(householdId, input)` — POST to `/transactions/expenses`, then refetch
- `createIncome(householdId, input)` — POST to `/transactions/income`, then refetch

Initial state: page 1, pageSize 20, type "all", all filter IDs empty.

Query param construction: only send `type` param for "expense" or "income"; "all" and "transfer" send no type param. For "transfer", client-side filtering happens in the component.

**New file:** `src/providers/transaction-store-provider.tsx` — same pattern as account-store-provider

**Modify:** `src/providers/store-providers.tsx` — add `TransactionStoreProvider` inside the nesting

## Step 4: Transaction List & Items

**New file:** `src/app/(authenticated)/transactions/transaction-list.tsx`

Props: `{ transactions: Transaction[] }`

Groups transactions by `transactionDate` using a `Map<string, Transaction[]>` (preserves insertion order from pre-sorted API data). Renders date headers ("Today", "Yesterday", "Apr 7, 2026") with transaction items below each.

**New file:** `src/app/(authenticated)/transactions/transaction-item.tsx`

Props: `{ transaction: Transaction }`

Compact row layout:

- Left: Badge (type indicator) + primary label (category name or "Transfer") + person·account in muted text
- Right: Amount (red for expense, green for income) + original currency if non-BDT

Badge variants: expense → `destructive`, income → `default`, transfer (transferGroupId !== null) → `outline`

Amount display: `formatCurrency(amountMinor)` for BDT, plus `formatOriginalCurrency(originalAmountMinor, originalCurrencyCode)` in muted text for non-BDT transactions.

**New file:** `src/app/(authenticated)/transactions/transaction-skeletons.tsx`

3 date groups × 2 items each, matching the item layout dimensions.

## Step 5: Creatable Combobox

**New file:** `src/app/(authenticated)/transactions/creatable-combobox.tsx`

A reusable component wrapping the base-ui Combobox for "pick existing OR create new" behavior.

Props:

```ts
{
  items: { id: string; name: string }[];
  value: string;           // selected id or new name
  isNew: boolean;          // whether value is a new name
  onSelect: (value: string, isNew: boolean) => void;
  placeholder: string;
  label: string;
}
```

Behavior:

- Renders all items from `items` prop as ComboboxItem entries
- When user types, items are filtered by name match
- If typed text doesn't exactly match any item, a "Create: [text]" option appears via ComboboxSeparator + special ComboboxItem
- On selecting an existing item: calls `onSelect(item.id, false)`
- On selecting "Create": calls `onSelect(typedText, true)`
- On clearing: calls `onSelect("", false)`

The expense drawer sends `categoryId` when `isNew=false`, `categoryName` when `isNew=true`. Same for origin in income drawer.

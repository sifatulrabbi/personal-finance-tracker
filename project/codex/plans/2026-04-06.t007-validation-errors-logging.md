# T-007 Plan: Validation, Error Envelopes, and Developer Logging

## Summary

Add lightweight server-side conventions for the API-heavy tickets that follow. This ticket should provide small reusable helpers, not a framework: request/body validation, common ID/date/money parsing, consistent JSON error envelopes, and basic structured developer logging hooks.

## Decisions

- Use existing Zod dependency for request-body schema validation.
- Use native `Response.json(...)` so helpers are usable from Next.js route handlers without adding a Next-specific dependency.
- Keep developer diagnostics out of client-facing error envelopes; log them through the logger hook instead.
- Use UUID-format ID parsing because database IDs are stored in Postgres `uuid` columns.
- Use strict `YYYY-MM-DD` date-only parsing for transaction/filter date inputs.
- Reuse `toMinorUnits` for money normalization so later write paths share existing money semantics.
- Add category-specific logging helpers for `auth`, `seed`, and `transfer` flows.

## Implementation

1. Add `src/libs/server/api/errors.ts` with `ApiError`, error factories, `toApiError`, and `createApiErrorResponse`.
2. Add `src/libs/server/api/validation.ts` with `parseJsonRequestBody`, `parseWithSchema`, `parseIdParam`, `parseDateOnlyInput`, and `normalizeMoneyInput`.
3. Add `src/libs/server/logger.ts` with a small structured logger and category helpers for auth, seed, and transfer events.
4. Add unit tests for predictable error envelopes, validation failure conversion, money/date/ID parsing, and logger output.
5. Mark T-007 complete after verification passes.

## Out of Scope

- Adding route handlers.
- Full observability infrastructure.
- Third-party logging vendors.
- Auth, transfer, account, people, category, or transaction business logic.

# Transaction Form Re-Implementation Plan

**Date:** 2026-04-14  
**Status:** Planning  
**Scope:** Full rewrite of expense/income/transfer creation form

## Problem

The current form implementation is fundamentally broken:

- Separate `ExpenseDrawer` / `IncomeDrawer` with duplicated logic
- Manual `useState` for every field — no form library, no validation
- Vaul Drawer containers cause pointer-event conflicts with Select/Combobox portals
- No client-side validation before API calls
- No transfer creation from the transactions page

## Solution

Single unified `TransactionSheet` (right side panel) with:

- **react-hook-form** for all form state management
- **Zod v4** client-side validation schemas
- **Type selector** (Tabs) inside the sheet — expense/income/transfer
- **Sheet** container (base-ui Dialog, not Vaul) — eliminates portal conflicts
- Dynamic field visibility based on transaction type

## Architecture

```
TransactionSheet
  ├── TypeSelector (Tabs — hidden in edit mode)
  ├── Form (react-hook-form, manual safeParse validation)
  │   ├── PersonField (Select)
  │   ├── AccountField (Select) or SourceAccount + DestAccount (transfer)
  │   ├── CategoryField (CreatableCombobox) — hidden for transfer
  │   ├── OriginField (CreatableCombobox) — income only
  │   ├── Amount + Currency row (InputGroup + Select)
  │   ├── DateField (native date input)
  │   └── DescriptionField (Textarea)
  └── SheetFooter (Submit + Cancel)
```

## Implementation Steps

1. `bun add react-hook-form @hookform/resolvers`
2. Add `createTransfer` action to `transaction-store.ts`
3. Create `src/libs/client/transaction-schemas.ts` (client Zod schemas + helpers)
4. Write schema unit tests
5. Add `error` prop to `CreatableCombobox`
6. Build `transaction-sheet.tsx`
7. Update `transactions-page-client.tsx`, delete old drawers
8. Write component tests
9. `bun run format`
